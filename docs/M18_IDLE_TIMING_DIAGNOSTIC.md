# M18 idle timing diagnostic

The [ordinary Release repeat](M18_IDLE_REPEAT_QUALIFICATION.json) misses the median engineering target. This opt-in diagnostic measures the remaining native work before selecting another correction. It is not a release candidate and its frame times cannot qualify ordinary Release.

Build with `scripts/build-performance-diagnostic.ps1 -DuckovPath <installed-game-directory>`. The existing script produces a separate five-file diagnostic package and a manifest containing its source inventory and hashes. Deployment remains a reversible UDS-only replacement after the user closes Duckov; restore the recorded ordinary package after diagnosis. Never alter profiles or saves for this check.

After launch, use the same Nullpunkt position, camera, SR-3M/MMG loadout and closed menus. Let the scene settle, then press F9 to reset counters and timers. Stay idle for about 30 seconds and press F10 once to write the bounded summary to Player.log. The agent suspends builds, tests and analysis until the user confirms the interval has ended. The initial startup interval is not controlled evidence. No CapFrameX acceptance capture is needed for this attribution check.

`M18Timing` records Stopwatch frequency, interval ticks, GC collection deltas and one fixed row per area. Each row contains `calls,total,max` in Stopwatch ticks; convert to milliseconds with `ticks * 1000 / frequency`. Total divided by calls gives mean inclusive duration. Update includes its child measurements and their instrumentation: do not sum nested rows or subtract them to claim precise release overhead. The timing scope excludes native Effect.Trigger/EffectAction.NotifyTriggered execution between Harmony prefix and finalizer; only UDS prefix and finalizer work is measured. The combat prefix rows distinguish UpdateTrigger, TickTrigger and other triggers. The clock callback is measured separately from Update.

Timers use fixed storage and value-type scopes. They record on the thread that reset the interval; other-thread attempts are counted separately and do not mix into these totals. Reset invalidates open scopes, and summary stops measurement. Timing handles close on early return and exceptions without changing the exception or native result. Logging, string formatting and GC-count reads happen only at the interval boundaries: the controlled baseline starts after the F9 reset log, and GC end counts are sampled before summary formatting. GC counts cover the process and cannot identify the allocating subsystem. Ordinary Release excludes the timing implementation and all timing call sites through `UDS_PERFORMANCE_DIAGNOSTICS`; the ordinary artifact audit rejects diagnostic calls.

The report can identify expensive UDS areas and callback frequency. It cannot separate every source of scene variance, native patch-dispatch overhead, background persistence cost or GC pauses; unmeasured work must remain explicit. A subsequent correction still needs independent review, ordinary package validation and fresh native acceptance captures.
