# M17 retained Item Use

Item Use renders successful raid uses through the retained shell. The accepted populated and empty references are [Item Use](../mockups/uds-ui-item-use.jpg) and [Item Use, empty](../mockups/uds-ui-item-use-empty.jpg). The implementation uses existing recorded data; no schema, adapter, inventory lookup, recipe inference or profile I/O is added by the view.

## Evidence rules

`ItemUseProjectionBinding` ties the tab to the shared factory publication, profile and exact generation. The factory copies strings, enums, counts and read-only collections; retained controls never own a profile, mutable aggregate or native item. Lifetime uses come from the existing `ItemUseReducer`, which rejects Base before aggregation. The view does not sum completed runs to replace lifetime data.

Use count, amount consumed and actual HP restored remain independent. Consumption preserves recorded Item, StackUnit and Durability dimensions; it does not add unlike units. A missing amount or `UnknownAmount` remains unavailable, including a zero-valued unknown sentinel. A known zero stack decrease is a valid observed zero. Known consumption alongside an unknown component retains its known component and its unavailable remainder. HP is the recorded positive health delta after native caps, never the item's advertised healing amount.

Canonical primary groups and captured effect tags remain separate. A multi-effect Food/Drink/Buff item contributes once to its primary group. Later proven healing promotion continues to use the existing reducer's canonical classification. Unknown/modded IDs stay distinct and use stable fallback names; display names do not join identities.

The [throwable release contract](M17_THROWABLES.md) remains unchanged. One successful native release counts one use even with no damage or no observed consumption. A recoverable throw can show one use and zero stack units consumed. Throwable rows retain primary group Special and effect Throwable. Supported recorded counts have no automatic Partial suffix or tracking-start/history explanation. A current throwable capability failure qualifies only affected rows and Special-group completeness; independent food, drink or healing values remain available. Missing generic-use capability likewise does not erase supported throwable releases. No anonymous legacy-only card or blanket earlier-history notice is rendered.

Recent-run item details use the exact run aggregate without borrowing a similarly named lifetime item. A run lacking historical item evidence cannot claim a proven empty breakdown; it displays the concise unavailable state when expanded. No missing history is reconstructed. Dates use local `yyyy-MM-dd - HH:mm:ss`. Run numbers follow the full Runs history order: descending start time, then ordinal exact Run ID. The recent list retains its existing end-time order and twelve-run bound. Titles summarize the recorded first and last map, collapsing a return to the same map; unknown endpoints stay unknown. Map counts use distinct recorded Map IDs only when ordered-route and segment capabilities are supported, every map is known, and neither the route nor its segments were repaired. Other map counts display Unavailable.

## Native layout and lifetime

The view borrows the existing native typography/material, native View run factory, outcome badge assets, `RunsHistoryButton` identity binding, `ButtonAnimation` and keyboard/controller feedback. It creates no replacement fonts or parallel icon framework. Decorative values and details are noninteractive; selection and hover/press tint remain separate.

Headings begin at the owning card's 30-pixel padding. The two document columns have a 40-pixel gap. Item names, effect text, values, filters and run titles use native measured width and height; filters wrap into additional rows rather than becoming inaccessible. Major cards have 20-pixel rounded corners; grouped expanded content and metric cards use the established 50% black surfaces. Top-level summary cards remain independent from the Most used items card.

Documents are rebuilt on publication, layout change or interaction, not each frame. Sorted vertical intervals select only visible rows plus overscan, and the existing bounded control pool recycles native controls. Rebinding cancels stale pointer identity; focus follows the exact row while visible and transfers to the viewport when wheel scrolling removes it. Switching columns and focusing a row uses the shared ancestor-reveal behavior. On close/disposal, the tab removes listeners, clears borrowed icon references, releases owned badge assets and destroys its own hierarchy.

Visual/layout conditions remain deterministic test or manual criteria. They are not part of production shell construction or panel availability.

## Qualification

`RetainedItemUseTests` exercises the existing reducer and throwable observation through the shared projection and immutable presentation, then the measured documents and selection policies. Native compilation establishes that the concrete renderer uses installed contracts. Game-independent tests do not execute Unity rendering, real raycast/focus order, native audio, live object counts or gameplay.

Minimum user-controlled checks: compare one raid consumable and one base use; compare a damaging throw, a miss and a recoverable throw; inspect actual consumed amount versus uses and HP; switch every group filter and item/run expansion; use View run; scroll both columns to both ends; repeat tab switching/open-close and test 1024×768 plus long names. Compare profile/export evidence after a normal restart. In-game visual, input, audio and gameplay acceptance remains pending under [M17_MANUAL_VALIDATION.md](M17_MANUAL_VALIDATION.md).
