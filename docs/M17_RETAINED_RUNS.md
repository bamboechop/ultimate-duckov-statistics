# Retained native Runs tab

The retained shell owns separate Overview and Runs content. Runs implements the accepted [Runs reference](../mockups/uds-ui-runs.jpg) using existing schema-17 data. It adds no tracking callback, schema member, gameplay object reference, export control, or runtime visual acceptance gate.

## Data and navigation

`RunsPresentationFactory` consumes an exact-generation `StatisticsPanelProjection`. It verifies profile, statistics, expected generation and every run generation, and rejects ambiguous duplicate run IDs. It creates immutable presentation strings and read-only collections, including copied terminal equipment and classified combat values from `RunDataProjection`. The view retains no `ProfileDocument`, `RunSummary`, native character, item, or slot.

History sorts by descending start time, then ordinal Run ID, with deterministic newest-to-oldest display numbers. `RunsSelection` initially selects the newest run, preserves a still-present ID within the same generation, and selects the newest remaining run after an ordinary valid refresh removes the selection. A changed generation starts a fresh selection. Overview navigation carries both the generation and exact card Run ID; a missing or mismatched target shows an explicit unavailable detail state rather than substituting another run. Ordinary selection remains available afterward.

The controller observes profile transitions and rebuilds presentations on completed profile-change notifications or a changed coordinator generation. Invalidation immediately removes old Runs values and hides old Overview content. Refresh replaces Overview content and Runs data inside the existing shell; header, tabs, back control and shell identity remain. No ordinary render reads a profile or rebuilds the data projection.

## Evidence and formatting

The ten summary values use run-scoped lifecycle, movement, combat, container, economy and item-use data. Full Runs timestamps convert stored UTC to local time and use `yyyy-MM-dd - HH:mm:ss`. Accuracy uses ranged hits divided by completed player projectiles; a missing denominator is unavailable. Missing or degraded evidence is qualified, and retained positive counts remain explicitly partial where completeness is lost.

Ranged and melee kills come directly from the classified partition. Effect/environmental kills are not reassigned to either section. Historical or unknown attack classification cannot create exact ranged/melee zeros. A current exact run remains exact alongside historical runs.

Terminal root slots retain the foundation's deterministic captured order. The baseline's ten positions render as two rows of five equal icon cards: 90 reference pixels, 16-pixel rounded corners, 2-pixel `#9298a4` borders, dark interiors and centered icons. Names and nested evidence do not contribute to card height. Native `TooltipsProvider` exposes captured slot names, item and attachment names, and completeness on hover or keyboard/controller focus. Its native disable callback clears the provider. Activating an occupied item with captured attachment slots (click or controller submit) also opens a dismissible, bounded captured-evidence panel using the existing retained text and scroll controls. The panel uses two columns: a native TypeID icon or empty dash on the left, and the captured item name above a smaller uppercase `#b1b1b1` slot label on the right. Rows preserve captured order; internal item IDs and nested paths are not displayed. Missing display names use unavailable wording while internal IDs remain available solely for icon resolution. Empty slots retain a dash and missing icons retain a question mark. The panel retains captured names with rich text disabled and supports arbitrarily long evidence without growing the icon card. This independent focus-detail affordance covers menu surfaces where the native tooltip canvas is absent or below the modal; it closes on run changes, tab switches and disposal. It adds no global tooltip framework or native-hierarchy mutation. Captured markup is neutralized before entering the native rich-text tooltip.

Proven empty is a muted dash; occupied items with unreadable icons show `?` on the normal interior; unavailable positions show `?` on a lighter interior. Missing root evidence fills anonymous unavailable positions up to ten without inventing slot IDs or claiming emptiness. Captured additional roots remain available as further rows, and the overall capture state remains available through the slot tooltip. The overlay omits the normal capture-state footer; incomplete attachment evidence retains its qualification. Empty roots and occupied items proven to have no attachment slots do not open an overlay. Occupied items with incomplete slot evidence remain inspectable. The equipment background has no tooltip or activation handler; only eligible individual item cards open details. No backpack, current equipment, duration aggregate or item-use inference supplies terminal equipment.

Each captured nested slot supplies one dot, in the existing deterministic captured order: occupied is solid white, proven empty is a muted ring. Incomplete evidence retains only the observed positions and adds an ellipsis; it never pads missing evidence with empty dots. Long nested trees pack their dots within the same card and retain captured item and slot names in the native tooltip.

Segment primary controls contain ordinal and map name. Separate smaller `#b1b1b1` details preserve duration/distance and available activity. `No combat or containers`, `No containers` and `No combat` require complete segment event, combat and container evidence. Combat absence checks firing, swings, hits, projectiles, damage and deaths, not only kills. Positive combat without kills remains visible. Incomplete evidence uses qualified counts/unavailable wording instead of proven-empty phrases.

## Layout and interaction

Runs uses the existing 2560×1440 reference transform and native TMP font/material with natural horizontal metrics. Content starts 40 reference pixels below the header. Desktop panels have a 1:2 width relationship, a 40-pixel gap, 30-pixel padding and the existing translucent rounded surfaces. Below 1180 viewport pixels, or when measured header text cannot leave a usable lower region, history precedes details in a vertically scrolling page, the summary uses two columns, and Route precedes Equipment and Combat. Desktop summary uses five columns and two rows, each with separate centered label/value controls. Labels are culture-aware uppercase and `#b1b1b1`; values are white. Values sit above their labels. Row-wide measured value heights align the labels consistently. The selected title has its own line; the badge, metadata and integrity/eligibility controls share a measured desktop row and wrap in order only when necessary. Route uses a separate white heading and smaller muted inline counts, aligned using native font ascent metrics. RANGED and MELEE use culture-aware uppercase. Measured text determines text heights; longer labels reflow rather than cause construction failure.

History uses measured row offsets and a recycled visible control pool with overscan; 10,000 data rows do not create 10,000 native buttons. History measurement is reused across selection changes. Route has a bounded clipped viewport containing every stored segment, including repeated maps, and a final outcome badge. Desktop header/metadata/summary are outside all scroll content. The history, lower Route card and lower Equipment/Combat column are independent bounded regions. The right lower region contains both headings and their cards; when those fit, both remain visible without a cue. Narrow layouts add a bounded outer page, retaining the independent lower regions. Wheel/controller input propagates only after the inner region reaches the relevant edge. Subtle white cues draw the actual horizontal container contour plus both quarter-circle corners, with the same radius as the background. History cues follow the outer history-panel edges; lower-region cues follow their own bounds. Fit shows no edge; top shows bottom; middle shows both; bottom shows top. Reflow and scrolling recalculate those states. No full selection frame or detached horizontal line is used.

The first Runs renderer reused a decorative Overview panel with `raycastTarget=false`, and all child graphics plus the feedback overlay were also non-raycastable. Consequently the underlying ScrollRect received hits and neither Button nor ButtonAnimation received row pointer callbacks. Runs now explicitly enables the full-row background raycast and `Button.interactable`; the shared canvas is selected through the existing GraphicRaycaster contract and Runs introduces no blocking CanvasGroup. Badge/text/highlight children remain non-raycastable. Every actionable row and Overview navigation button attaches native `ButtonAnimation`. The installed component supplies pointer hover/click sounds; it has no selection/submit interface, so focus and submit forward those callbacks. A separate native UI color transition supplies hover/press/focus feedback while the selected row retains its orange background. Row focus travels through the virtual history and remains associated with Run ID. A pointer-down binding captures generation and exact Run ID; rebind, wheel movement, drag or disable cancels that click. Submit uses the currently focused binding and fails closed on a generation mismatch. One listener per control reads the binding; recycling cannot silently change a pressed or focused action. Focus reveals ancestors as needed. The shared tab row is horizontally clipped/scrollable, with selected or focused tabs revealed without changing native label widths.

Scroll state is retained across tab switches and valid refreshes where extents still permit it. Selecting another run, a changed selection after refresh, or explicit Overview routing resets lower-column/route offsets. Suspension restores lower offsets only for the same generation and Run ID. Row listeners attach once per pooled control; shell disposal removes listeners and releases owned badge assets and the common material. Overflow is never a fatal acceptance condition.

## Qualification boundary

`RetainedRunsTests` exercises ordering, generation checks, exact routing, selection changes, immutable values, outcomes, empty/partial data, terminal/nested evidence, icon fallbacks, classified kills, route order, long histories, measured row wrapping, scroll propagation, overflow edges, focus reveal and pooled listener/resource lifetime. Existing foundation and Overview/shared-shell suites remain separate regressions. These game-independent tests do not execute Unity's renderer or certify native screenshots, audible feedback or live GameObject counts.

Manual qualification must use the complete native Runs protocol in [M17_MANUAL_VALIDATION.md](M17_MANUAL_VALIDATION.md). Equipment identity/completeness is available through native tooltips, so long identity strings do not expand the persistent cards. The desktop detail header and summary remain fixed while the lower regions scroll independently. Ranged kills are shown alongside melee kills to make the classification explicit. Native typography differences, generated fallback badge glyphs and translucent surfaces are intentional; no blur or copied game image is shipped.

## Installed native evidence for the Runs correction

Read-only assembly and serialized-resource inspection on 2026-09-05 used Duckov 2.3.30 / Steam build 24013657 / Unity 2022.3.62f2. `resources.assets` SHA-256 is `93c4ab6ad71fdb3bf4a331bbb2ac6bc2f7db7b0f12efe60dd43ea019ab2e543d`. No game process was launched or controlled.

`GameplayDataSettings.UIPrefabs.ScrollRect` resolves from the serialized `UIPrefabs` object (path ID 76739) to ScrollRect 101346. Its configuration is vertical, Elastic, sensitivity 1, elasticity 0.1, inertia enabled and deceleration 0.135. Runs copies those settings from the installed prefab without instantiating its hierarchy or listeners. Unity's installed `ScrollRect.OnScroll` applies wheel deltas directly; drag inertia and elastic recovery use its native LateUpdate. This is native configuration reuse, not a claim of animated wheel smoothing. Controller scroll commands use the same sensitivity; row navigation uses exact index focus/reveal. The former Runs wheel/controller increments were 60/100.

`ButtonAnimation` implements pointer enter/exit/down/up and posts `UI/hover` and `UI/click`. It does not implement select/submit. Runs forwards keyboard focus/submit to those native callbacks and keeps the persistent orange row background separate from the interaction tint.

`ItemAssetsCollection.GetMetaData(int)` checks dynamic entries before built-ins and returns default metadata for missing entries. `ItemMetaData` exposes both `id` and `icon`. Native capture uses `duckov:item:`, `duckov:weapon:` and `duckov:totem:` followed by TypeID, but the first renderer accepted only the first form. The correction accepts all three captured forms, validates returned metadata identity and treats the native fallback sprite as unresolved. Runs then supplies its deterministic fallback without discarding captured identity. The shared resolver retains native fallback behavior for its other consumers.

Captured Kriegsaxt (`duckov:weapon:306`), SR-3M (`duckov:weapon:736`) and MMG (`duckov:weapon:256`) agree with serialized metadata IDs 306, 736 and 256 and non-null sprite references 6359, 5212 and 5257 respectively. The entire 1,569-entry metadata collection parsed to its exact serialized length of 263,068 bytes. There is no name-to-icon lookup table in shipping code.

The deterministic tests execute the production row-button subclass against a minimal native event boundary, exercise presentation/geometry policies, and check Unity-only composition wiring. They do not execute the native renderer, audible feedback, tooltip placement or the real EventSystem raycast ordering. Those remain manual acceptance requirements.
