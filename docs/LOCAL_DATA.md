# Local data and privacy

UDS performs no telemetry, network reporting, account login or remote synchronization. Runtime data stays below Duckov's `Application.persistentDataPath`, in `UltimateDuckovStatistics/v1/`. The packaged mod never writes Duckov saves. About contains plain translation information directing volunteers to Steam Workshop comments; it has no external links or browser actions. UDS makes no background web requests or automatic uploads.

Per-save data includes the UDS generation, native save slot, read-only save fingerprint/SaveTime evidence, aggregate statistics, compact run summaries, capability state, bounded diagnostics, session/active-run checkpoints, atomic backups and exports. Replaced generations are archived read-only. Run history and user-created exports persist; diagnostic logs and correlation caches are bounded. Removing the mod package does not remove these files.

Recorded base movement stores an aggregate distance, first-observation UTC time and known-gap flag in the current v1 format. It does not store coordinates or native actor identities. A profile without a base observation remains unrecorded until collection begins; a valid stationary observation can establish zero. Exports include the same raid/base/combined projection and coverage information shown in Overview.

Version 1.0.0 establishes `uds-profile-v1`, schema 1 in the `v1` directory. This deliberately starts fresh from the development schema 18 used by the release candidates and early local 1.0.0 preparation builds. Those profiles are incompatible and are not converted; if left on disk, they are archived intact before fresh statistics begin. There is no supported import of `0.x` profiles. Valid schema-1 reinstallation, including a switch from manual installation to Workshop, preserves current data. Invalid current files use validated primary/backup/temporary recovery; incompatible formats remain protected. A user's explicit one-time cleanup of obsolete development profiles does not change that shipping preservation policy. Do not remove validators, checkpoints or temporary files to force a damaged primary to load.

Diagnostics exports a frozen generation snapshot as JSON and CSV. Exports contain gameplay identities, timestamps and statistics and may contain mod/item names supplied by native content. Diagnostics can contain local paths and error details; the UI abbreviates paths where appropriate. Inspect exported files and logs before sharing them. No sharing happens automatically.

Reset requires a deliberate confirmation, starts with Cancel focused, archives the current UDS generation and starts a new one. It does not change the Duckov save. A durability failure can leave the request pending; retained data and bounded retries take priority over pretending that reset succeeded. Clipboard failure does not turn a successfully written export into a failed export.

Build artifacts use normalized `/_/uds/` source identities. Post-build/package audits scan PE/PDB metadata and UTF-8/UTF-16 payloads for builder identities and absolute machine paths. PNG metadata is scanned separately, including decompressed text/profile chunks; compressed pixel data and palettes are not treated as text. PDBs stay outside the install package, whose current six-file inventory includes the Workshop preview. Source paths, raw performance sidecars and local qualification logs can contain machine-specific information and remain local unless explicitly shared.
