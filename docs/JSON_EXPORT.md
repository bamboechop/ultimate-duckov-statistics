# JSON export

Diagnostics writes one `statistics.zip` inside the existing timestamp-and-generation export directory. The archive contains exactly one file, `statistics.json`. Extract it with a standard ZIP tool to read or analyze the JSON. CSV export has been retired. Existing exports are not changed or removed. Historical milestone and qualification documents describe the CSV files produced by those earlier builds.

The JSON contract is unchanged: schema 1, generation/slot/revision and export time, item totals and groups, completed runs and routes, records, combat and equipment evidence, capabilities, economy/holdings, crafting, world time and raid/base distance. Original numeric precision and unknown, unavailable, partial and repaired-data evidence remain intact. It is a structured statistics export, not an interchangeable SQLite database or profile backup; manual restore/import remains a separate feature.

Export captures a detached generation and revision after the existing durability boundary. The SQLite snapshot remains valid across subsequent saves, profile changes and reset. Run details are projected one at a time; the writer does not materialize the complete run history or a whole-file JSON string. It streams UTF-8 JSON directly into a ZIP entry using the framework's `CompressionLevel.Optimal`, without writing a separate uncompressed file or adding a dependency. It finalizes the entry and ZIP central directory in `statistics.zip.tmp`, flushes the file to disk, and only then publishes `statistics.zip`. A failed write propagates to the existing failure UI and does not publish an incomplete ZIP. A pre-existing final export is never overwritten. Panel close and profile changes still prevent stale completion messages.

ZIP serialization and compression run on the existing background worker for an explicit Diagnostics export. This does not change normal gameplay capture, SQLite persistence, schema versions, or database compression.

Automated ZIP validation on 2026-09-13: Debug and Release each passed 2,205 main tests and 90 shell tests. The archive tests verify exactly one entry, byte-exact JSON after decompression, Unicode and numeric precision, compression, frozen revision/generation ownership, the 1,000-run export, failure while reading detached run details without publishing a final ZIP, and no overwrite on a destination collision. The native Release build, installed contract probe, changed-source whitespace check, and 13-file package/IL audit passed. No new packaged dependency is required.

Before the ZIP wrapper was added, Debug and Release each passed 2,202 main tests and 90 shell tests. Coverage included one-file output inventory, byte-equal streamed/materialized JSON, detached revision and generation/reset isolation, current/partial/historical evidence, a 1,000-run export, and failure without overwriting an existing export. The native Release build, installed contract probe, changed-source whitespace check and package/IL audit passed.

Native acceptance of that uncompressed JSON-only build on 2026-09-13: the deployed package passed all 13 installed-file hash checks, and the user exported from the game and confirmed that the new export directory contained only `statistics.json`. Its 1,940,495-byte JSON was then measured in memory: a standard-compression ZIP containing it occupied 195,313 bytes (89.93% smaller), with byte-exact decompression. This is one profile measurement, not a universal compression ratio. Native ZIP acceptance on 2026-09-13: all 13 deployed files matched the packaged build, and the user confirmed that exporting and opening the ZIP worked.
